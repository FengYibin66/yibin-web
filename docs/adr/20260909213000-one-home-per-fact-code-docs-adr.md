# 20260909213000. 每条事实只有一个落点：代码写不变量、AGENTS.md 写现状、ADR 写决策

- 状态：已接受
- 索引：全仓注释已长到 8146 行（312 个 `.ts/.tsx` 文件，占 17%；高密度文件 50–89% 是注释），而其中大部分与 ADR、`AGENTS.md`、提交说明**逐条重复**——同一件事有三四个落点，改一处其余静默过期。决定：① **代码注释只写代码读不出来的东西**（不变量、单位、外部约束、反直觉取值的来源、已知会再咬人的陷阱一句话）；② 「为什么选 A 不选 B」只进 ADR，代码里最多留一个 ADR 编号；③ 「现在是什么样、有哪些约定」只进 `AGENTS.md`；④ 自述式的踩坑经过（「我第一版怎么错的」）不进代码，除非那个坑会再咬下一个人，且压成一句结论。判定原则：**每条事实只有一个落点；重复的那几份不是冗余，是将来会互相矛盾的四个事实来源**
- 日期：2026-09-09

## 背景

这个仓库的注释密度是刻意养出来的：`AGENTS.md` 要求「说得出为什么」，多条门禁的文件头写着变异测试的结果，而 2026-09-09 的响应式那四批把这个做法推到了极端——单个 CSS 属性挂 8 行注释，测试文件 30 行的 `describe` 头，`lib/layout/breakpoints.ts` 36 行里 32 行是注释。

问题不是「注释多」，是**同一条事实有多个落点**。以 `breakpoints.ts` 的 `NARROW_MAX = 767.98` 为例，「768 此前有三个表示且边界语义相反」这件事同时写在：

- `lib/layout/breakpoints.ts` 的文件头（26 行）
- `ADR 20260909182319` 的背景一节
- `apps/resume/AGENTS.md` 的屏角一节
- PR #46 的提交说明

四份。其中三份是副本。副本的代价不是占地方，是**它们会分叉**：断点改了，改的人会改代码和最近的那份文档，另外两份静默变成假事实。这个仓库已经为「文档与实现分叉」付过一次大钱——`docs/ARCHITECTURE.md` 长期写「Portal & Auto-Wechat share MySQL」而实现从来是 libSQL 单文件（ADR 20260822120802 才纠正），根 `CLAUDE.md` 至今把它作为反面教材。注释是文档的一种，只是没人给它做 `--check`。

## 决定

### 三个落点，各管一件事

| 落点 | 写什么 | 不写什么 |
|------|--------|----------|
| 代码注释 | 不变量、单位、坐标系、外部系统的约束、反直觉取值的推导、会再咬人的陷阱（一句） | 决策理由、备选方案、历史、代码在做什么 |
| `AGENTS.md` | 当前现状与目录约定、踩过且会再踩的坑 | 决策过程、逐字的代码细节 |
| ADR | 为什么选 A 不选 B、备选与代价、验证方式 | 现状（会过期，写了也不许改） |

代码里引用决策用编号：`// 见 ADR 20260909182319`，不复述内容。

### 判定：删之前问一句「删了会怎样」

- 删了**下一个人会写出错的代码** → 留（是不变量或陷阱），压到一两句
- 删了**评审无法回答「要不要这么做」** → 搬 ADR
- 删了**没人知道现在是什么形态** → 搬 `AGENTS.md`
- 删了**只是少了一段故事** → 删

### 不做什么

- **不设注释密度门禁。** 密度不是质量的度量：`lib/lab/domain/corridor/world.ts` 的坐标系说明该留，`tourHintStorage.ts` 里 55 行讲「E2E 为什么抓不稳」该走 ADR，两者密度接近。指标会把「删掉该留的」也算成达标。
- **不回头重写历史 ADR。** ADR 不可变（ADR 20260822120805），本决定只约束往后新写的与本次清理触及的。
- **不动 `docs/reviews/`**。验收报告的性质就是叙述当时看到了什么，长是应该的。

## 影响

- 一次全量清理：`apps/resume` 的 `.ts/.tsx`，优先高密度文件；内容已在 ADR / `AGENTS.md` 的直接删并留编号
- 提交说明同样适用：说明写「改了什么、怎么验的」，决策理由给 ADR 编号
- 根 `CLAUDE.md` 的「AI 协作硬约束」加一条，指向本 ADR

## 验证

清理后重跑 `pnpm test` / `pnpm type-check` / `pnpm build` / `pnpm test:e2e`：注释不参与构建，任何一条变红都说明删到了代码。另外抽查被删内容是否在 ADR 或 `AGENTS.md` 里能找到——找不到的要么补回一句，要么补进对应落点。
