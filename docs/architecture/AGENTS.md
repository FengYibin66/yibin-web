# docs/architecture/

架构的**描述性**文档——"系统长什么样、打算长成什么样"。决策理由不在这里，在 `../adr/`。

这个目录在 `docs/AGENTS.md` 的表里登记了很久，但直到 2026-09-07 才真的建出来——
之前这类内容散在 `../ARCHITECTURE.md`（现状）与各 ADR 的背景段里。

## 内容

| 文件 | 说明 |
|------|------|
| `platform-roadmap.md` | 平台路线图：交付流水线 / IaC 对齐、统一控制台。**是计划，不是决策**——每一期落地前先写 ADR |

## 规则

- 这里写"是什么 / 想成为什么"，不写"为什么选 A 不选 B"。有备选方案的选择去 `../adr/`。
- 路线图里的每个「待拍板」在被决定后，改成指向对应 ADR 的链接，不要留一个已经过期的问句。
- 与 `../ARCHITECTURE.md` 的分工：那份是**当前**结构的快照；这里的路线图是**差距与方向**。
  两者都要在同一 PR 内随实现更新（`docs/AGENTS.md` 的同步义务）。
